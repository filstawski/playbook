# 8. GitHub

Pull requests, repositories, issues and dependency updates on GitHub. The
step-by-step PR procedure is the
[git-pull-requests](../../skills/git/git-pull-requests/SKILL.md) skill.

| File | Covers |
| --- | --- |
| [pull-requests.md](pull-requests.md) | everything through a PR and the user merges, one concern per PR, the template, no screenshots/attribution/client names, live PR state, stacked PRs against main, watching CI |
| [repositories.md](repositories.md) | private by default and only when asked, pre-push checks, gh credential helper, issues with labels, Dependabot setup and triage |

## Know these first

- **The agent opens PRs; the user reads and merges,** only on green.
- **Check the PR's real state on GitHub before every status report.**
- **Stacked PRs always target main.**
- **No AI attribution, session links or screenshots in PRs.**
