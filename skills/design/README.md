# design

How interfaces should look and feel: the visual direction and the process
of finding it, and the detail pass that makes a screen feel finished. Motion
has its own skill under [website/](../website/README.md).

- **[design-taste](design-taste/SKILL.md)** — start here for any design
  or redesign work. Write a design read first, take the identity from the
  business, show directions side by side, audit before a redesign, read the
  user's feedback correctly, avoid generic and AI-looking patterns, and run
  the pre-flight check.
- **[design-interface-polish](design-interface-polish/SKILL.md)** — the
  detail pass and review format. Concentric radii, optical alignment,
  neutral elevation, hit areas, text wrapping, icons, press and hover
  feedback, transition hygiene.

The rules both skills apply are in
[guidelines/design-guidelines/](../../guidelines/design-guidelines/README.md)
and [guidelines/ui-ux/](../../guidelines/ui-ux/README.md).

## How these relate

`design-taste` decides *what* the interface should be. `design-interface-polish`
makes sure *how* it is built doesn't undermine that. Run taste first: a
polished version of the wrong direction is still the wrong direction. Both
are rebuilt from third-party skills (MIT); see each skill's README for
sources and licence notices.
