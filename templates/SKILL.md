## Rule

State the practice as an instruction an agent (or future me) can follow
directly. Include real, runnable code examples wherever the practice is
about how code should be structured — not just a description of the shape,
the actual shape. Don't trim for length; a complete reference beats a short
one. One practice per file — if this needs sections for genuinely unrelated
ideas, split it into two skills and cross-link them instead of cramming
both in here.

## Why

The reasoning, tradeoff, or incident behind the rule. Without this, the rule
calcifies and gets applied to cases it was never meant for.

## Exceptions

When this doesn't apply, or hasn't been tested yet. A rule with no stated
exceptions is usually applied too broadly.
